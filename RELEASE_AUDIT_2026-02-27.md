# NebulaClash Pre-Release Audit (2026-02-27)

## Critical (fix before release)

1. Монетизация не интегрирована с зачислением валюты.
- Факты: покупка открывает внешнюю ссылку, а не backend-инвойс: `src/App.tsx:303`, `src/App.tsx:307`.
- Факты: баланс монет хранится локально в браузере: `src/App.tsx:363`, `src/App.tsx:371`.
- Риск: после оплаты пользователь не получает монеты автоматически; монеты можно накрутить через localStorage.
- Минимальный фикс: связать `buyCoinsPack` с `/api/payments/lava/create-invoice` и после webhook обновлять баланс через `/api/wallet`.

2. В UI явно написано, что онлайн-оплата отключена.
- Факт: `src/components/ShopModal.tsx:43`.
- Риск: прямое падение конверсии и доверия в момент релиза.
- Минимальный фикс: заменить текст на рабочий сценарий оплаты или скрыть блок до полной интеграции.

3. Прод-ключи и контакты лежат в репозитории (`.env.production`).
- Факты: `./.env.production:1`, `./.env.production:3`, `./.env.production:6`, `./.env.production:7`, `./.env.production:8`.
- Риск: утечка конфигурации, неуправляемый доступ к аналитике/проектам.
- Минимальный фикс: удалить секреты из git, оставить только `.env.example`, заменить ключи (rotate) в сервисах.

## High

1. Analytics/monitoring включены хардкодом даже без env.
- Факты: дефолтные GA/YM в коде: `src/analytics.ts:18`, `src/analytics.ts:19`.
- Факт: дефолтный Sentry DSN в коде: `src/monitoring.ts:4`.
- Риск: тестовый/чужой трафик загрязняет прод-метрики, сложнее отладка.
- Минимальный фикс: убрать дефолтные идентификаторы, включать только через env.

2. Sentry отправляет PII по умолчанию.
- Факт: `src/monitoring.ts:25`.
- Риск: юридические вопросы и лишние персональные данные в логах.
- Минимальный фикс: `sendDefaultPii: false`, добавить явное согласие пользователя на аналитику.

3. API кошелька без аутентификации и с открытым CORS.
- Факты: `Access-Control-Allow-Origin: *` в `server/index.mjs:75`, `server/index.mjs:353`.
- Факт: `POST /api/wallet/spend` без auth: `server/index.mjs:370`.
- Риск: сторонние сайты/скрипты могут дергать API, при знании `playerId` списывать монеты.
- Минимальный фикс: auth token/JWT + CORS whitelist + подпись запросов на spend.

4. Данные кошельков/заказов в локальном JSON-файле.
- Факт: `wallet-state.json` через `server/index.mjs:10`.
- Риск: потеря данных при перезапуске/деплое на stateless-хостинг, гонки записи.
- Минимальный фикс: вынести в БД (Postgres/Supabase/SQLite с бэкапом как минимум).

## Medium

1. Линтер не проходит (25 errors, 7 warnings).
- Ключевые ошибки: `src/App.tsx` (серии `set-state-in-effect`), `src/logic/boardUtils.ts` (`any`), `src/components/Tile.tsx` (`any`).
- Риск: технический долг и риск регрессий в релизной ветке.

2. Сборка в текущем окружении не проверена из-за `spawn EPERM`.
- Команда: `npm run build`.
- Риск: нет подтверждения, что финальный билд собирается в чистой среде.
- Действие: проверить build на целевой машине/CI.

3. README не отражает продуктовый статус проекта (остался шаблон Vite в начале).
- Файл: `README.md`.
- Риск: сложнее поддержка и передача проекта.

## Fast priority plan (solo + AI)

1. День 1-2: закрыть монетизацию end-to-end.
- `buyCoinsPack -> create-invoice -> redirect -> webhook -> wallet credit -> UI refresh balance`.

2. День 2: убрать ключи из репо + ротация ключей.

3. День 2-3: API hardening.
- auth, CORS whitelist, rate-limit, basic audit logs.

4. День 3: минимальный QA регресс.
- оплата успех/ошибка/дубль webhook/таймаут/повторный вход.

5. День 4: lint cleanup критичных мест и финальная build-проверка.

- [ ] Оплата проходит в production-сценарии и автоматически начисляет валюту.
- [ ] Нет секретов в git.
- [ ] Включена auth-защита API и CORS whitelist.
- [ ] Есть crash monitoring без лишнего PII.
- [ ] Сборка проходит в чистом окружении.
- [ ] Готовы оферта/политика/возвраты/контакты (актуальные).
